# ReadAside 评测记录与执行规范

本目录是 ReadAside 上下文与回答依据质量的唯一记录入口。目标是让每次修改后都能回答四个问题：证据有没有丢、发送内容是否变多或变少、隐藏证据有没有被错误放行、哪些具体问题发生了变化。

## 日常查看

优先运行：

```bash
npm run evaluate:context:compare
```

它会用同一组 30 题分别检查短页完整结构化策略和确定性扩展长页检索，并与 [`snapshots/0.11.0.json`](./snapshots/0.11.0.json) 逐题比较：

- 短页是否发送全部结构化内容块且覆盖必需证据；
- 长页证据召回和上下文缩减变化；
- 长页自动全文回退变化；
- 每道题的 Recall、缩减比例、模式和采用块集合变化。

再运行强制门槛：

```bash
npm run evaluate:context:gate
npm run evaluate:citations
npm run evaluate:evidence
```

当前门槛是短页全部结构化内容和必需证据覆盖均为 100%，长页检索证据召回不低于 85%、每个数据集的缩减中位数不低于 60%，以及 2,000 块压力测试 p95 低于 100 ms。历史块引用和当前隐藏证据评测都要求固定用例全部通过且错误放行为 0。`npm run verify` 会自动展示检索快照对比并运行两类证据评测，但发布前仍应显式运行检索 gate。

## 记录分层

1. **问题与证据标注**：`test/evaluation/*.questions.json`。除非发现标注错误，否则不为提高数字改题。
2. **机器可读快照**：`docs/evaluation/snapshots/<version>.json`。记录逐题采用块，发布后不覆盖。
3. **人类可读报告**：`docs/evaluation/*.md`。解释范围、规则变化、指标和限制。
4. **真实网页人工验收**：复制 [`manual-validation-template.md`](./manual-validation-template.md) 新建记录，只写页面类型和现象，不保存私密页面正文。

## 上下文相关修改的完成标准

任何涉及页面分块、表格序列化、检索评分、邻块扩展、上下文预算或 Prompt 页面上下文的修改，在完成前必须：

1. 运行 `npm run evaluate:context:compare`，检查并解释所有逐题变化。
2. 运行 `npm run evaluate:context:gate`，不得静默接受门槛回退。
3. 运行 `npm run verify`，保证读取、选区、问答、预览和安全回归测试正常。
4. 若准备形成新版本，新建该版本的 JSON 快照和 Markdown 报告；旧文件保持不变。
5. 若指标改善但真实回答变差，以人工验收为准，记录失败案例并补充可公开复现的虚构夹具。

涉及隐藏证据、工具流解析、本地校验或定位按钮的修改，必须运行 `npm run evaluate:evidence`；历史块引用模块有改动时再运行 `npm run evaluate:citations`。不要把真实模型输出写进固定数据集；模型是否调用工具、原句是否充分支撑结论和定位是否准确，记录在人工验收表中。

## 怎样理解结果

- 短页口径只验证预算内页面是否发送全部结构化内容块；长页口径才衡量块级检索的 `Recall@K` 与缩减。
- `Recall@K` 只说明人工标注的证据块进入了发送集合，不代表模型回答正确。
- 长页缩减比例只说明发送字符减少，不代表越高越好；证据召回优先。确定性中性填充也不代表真实网页分布。
- 逐题采用块变化不一定是回归，但必须能解释。
- 性能数字受机器负载影响，主要用于识别数量级回退。
- 私密网页、真实 API Key 和完整模型请求不得写入评测记录。
- 隐藏证据确定性评测只证明白名单、逐字和唯一性校验行为，不证明模型回答事实正确、工具调用稳定或原句充分支撑结论。
- “本次发送预览”记录系统采用的内容；定位按钮只表示模型实际返回且通过校验的核心原文。自动模式回退全文、模型未调用工具或证据被拒绝时，没有按钮属于预期降级，不应误记为校验器失败。
